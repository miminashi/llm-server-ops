2.  **Analyze Topic 1: GPU GEMV Bandwidth-Bound Nature**
   - *What is GEMV?* Matrix-vector multiplication: $y = A \times x$, where $A$ is $M \times N$, $x$ is $N \times 1$, $y$ is $M \times 1$.
   - *Compute vs. Memory:* Each output element $y_i$ requires $N$ multiply-add operations. Total FLOPs = $2MN$. Total memory reads: Matrix $A$ ($MN$ elements) + Vector $x$ ($N$ elements). Total memory writes: Vector $y$ ($M$ elements).
   - *Arithmetic Intensity (AI):* AI = FLOPs / Bytes. For GEMV, AI ≈ $2MN / (MN \cdot \text{bytes} + N \cdot \text{bytes} + M \cdot \text{bytes}) \approx 2 / \text{bytes}$ (assuming $M, N$ large). Typically 2-4 bytes per element (FP32=4, FP16=2, INT8=1). So AI is very low (~0.5-2 FLOPs/Byte).
   - *GPU Architecture:* GPUs have high peak compute (TFLOPS) but limited memory bandwidth (GB/s). When AI is low, the operation is limited by memory bandwidth, not compute units.
   - *Conclusion:* GEMV is bandwidth-bound because it performs very few arithmetic operations per byte of data transferred. The GPU's compute units sit idle waiting for data.

3.  **Analyze Topic 2: Quantization Block Memory Layout & Effective Bandwidth**
   - *What is quantization?* Reducing precision (e.g., FP16 -> INT4/INT8) to save memory and bandwidth. Usually done in blocks (e.g., 16x16, 32x32) with per-block scaling factors.
   - *Memory Layout:* How quantized weights are stored matters. Common layouts: row-major, column-major, channel-interleaved, block-compressed, etc. Also, how scaling factors are stored (per-tensor, per-channel, per-block).
   - *Effective Bandwidth:* The theoretical max bandwidth assumes contiguous, aligned, full-width transfers. Real-world effective bandwidth depends on:
     - *Access Pattern:* Does the kernel read data sequentially or with strided/random access? Strided access causes cache misses and inefficient DRAM row buffer hits.
     - *Data Contiguity:* If quantized blocks are stored with padding, or if scaling factors are scattered, the memory controller can't coalesce accesses efficiently.
     - *Decoding Overhead:* Quantized data often needs on-the-fly dequantization. If the layout requires fetching multiple small chunks to decode one block, it increases traffic or causes misaligned accesses.
     - *Memory Controller Efficiency:* Modern GPUs use 32-byte/128-byte cache lines and DRAM channels. Layouts that align with these boundaries maximize bandwidth. Poor layouts cause partial line fills, wasting bandwidth.
   - *Conclusion:* The memory layout dictates access patterns, coalescing efficiency, and cache/DRAM utilization. Poor layouts fragment transfers, reduce row buffer hits, and force extra reads for metadata (scales), lowering effective bandwidth.
